# 🩺 MediBook — ექიმთან ვიზიტების დაჯავშნის სისტემა

**MediBook** არის Full-Stack ვებაპლიკაცია, რომელიც მომხმარებლებს საშუალებას აძლევს მოიძიონ ექიმები, შეარჩიონ თავისუფალი დრო და დაჯავშნონ ვიზიტები ონლაინ.

პროექტი შექმნილია Frontend პროგრამირების ფინალური დავალების ფარგლებში და მოიცავს როგორც მომხმარებლის ინტერფეისს, ისე Backend API-სა და მონაცემთა ბაზას.

## 🚀 ძირითადი ფუნქციონალი

- მომხმარებლის რეგისტრაცია და ავტორიზაცია
- როლებზე დაფუძნებული წვდომა (Patient, Doctor, Admin)
- ექიმების სიის დათვალიერება და ძიება
- ექიმის სპეციალობის, კლინიკისა და გამოცდილების ნახვა
- თავისუფალი საათების შემოწმება
- ექიმთან ვიზიტის დაჯავშნა
- დაჯავშნის ფორმაში პაციენტის სახელისა და ელფოსტის მითითება
- საკუთარი ვიზიტების ნახვა
- ადმინისტრატორისა და ექიმის ცალკეული Dashboard-ები
- ვიზიტებისა და მომხმარებლების მონაცემების შენახვა SQLite ბაზაში

## 👥 მომხმარებლის როლები

### 👤 Patient — პაციენტი

პაციენტს შეუძლია:

- ანგარიშის შექმნა და სისტემაში შესვლა
- ექიმების მოძიება და დათვალიერება
- სასურველი ექიმის, თარიღისა და დროის არჩევა
- ვიზიტის დაჯავშნისას პაციენტის მონაცემების შეყვანა
- საკუთარი დაჯავშნილი ვიზიტების ნახვა

### 👨‍⚕️ Doctor — ექიმი

ექიმს აქვს საკუთარი Dashboard, სადაც შეუძლია:

- მასთან დაჯავშნილი ვიზიტების ნახვა
- პაციენტების სახელებისა და ვიზიტის დეტალების ნახვა
- მხოლოდ საკუთარ ვიზიტებზე წვდომა

Doctor ანგარიში ადმინისტრატორის მიერ უკავშირდება შესაბამის ექიმს.

### 🛡️ Admin — ადმინისტრატორი

ადმინისტრატორს შეუძლია:

- ადმინისტრატორის Dashboard-ის ნახვა
- ექიმების დამატება, რედაქტირება და წაშლა
- სისტემაში არსებული პაციენტების რაოდენობის ნახვა
- პაციენტებისა და ვიზიტების მონაცემების დათვალიერება
- Doctor ანგარიშის დაკავშირება კონკრეტულ ექიმთან

სისტემაში შესვლის შემდეგ მომხმარებელი გადამისამართდება საკუთარი როლის შესაბამის გვერდზე.

## 🛠️ გამოყენებული ტექნოლოგიები

### Frontend

- **React** — მომხმარებლის ინტერფეისი
- **Vite** — პროექტის გაშვება და აწყობა
- **React Router** — გვერდებს შორის ნავიგაცია
- **Zustand** — მდგომარეობის მართვა
- **Zod** — მონაცემების ვალიდაცია
- **CSS** — დიზაინი და რესპონსიული ინტერფეისი

### Backend

- **Node.js** — სერვერული გარემო
- **Express.js** — REST API
- **SQLite** და **better-sqlite3** — მონაცემთა ბაზა
- **JWT** — ავტორიზაცია
- **bcryptjs** — პაროლების ჰეშირება
- **Zod** — API მოთხოვნების ვალიდაცია

## 💻 პროექტის ლოკალურად გაშვება

პროექტის გასაშვებად საჭიროა **Node.js** და **npm**.

### 1. რეპოზიტორიის ჩამოტვირთვა

```bash
git clone https://github.com/takkh19/MediBook.git
cd MediBook
```

### 2. Frontend-ის დამოკიდებულებების დაყენება

```bash
npm install
```

### 3. Backend-ის დამოკიდებულებების დაყენება

```bash
cd server
npm install
```

### 4. გარემოს ცვლადების კონფიგურაცია

`server` საქაღალდეში შექმენი `.env` ფაილი:

```env
PORT=3001
JWT_SECRET=replace_with_a_long_random_secret_key
CLIENT_ORIGIN=http://localhost:5173
```

პროექტის მთავარ საქაღალდეში შექმენი `.env.local`:

```env
VITE_API_URL=http://localhost:3001
```

**უსაფრთხოება:** რეალური `JWT_SECRET`, პაროლები და სხვა საიდუმლო მონაცემები არ უნდა აიტვირთოს GitHub-ზე.

### 5. Backend-ის გაშვება

`server` საქაღალდიდან:

```bash
node index.js
```

Backend ხელმისაწვდომი იქნება მისამართზე:

`http://localhost:3001`

### 6. Frontend-ის გაშვება

გახსენი მეორე ტერმინალი და პროექტის მთავარ საქაღალდეში გაუშვი:

```bash
npm run dev
```

Frontend ხელმისაწვდომი იქნება მისამართზე:

`http://localhost:5173/MediBook/`

## 🔐 ავტორიზაცია და უსაფრთხოება

MediBook იყენებს JWT-ზე დაფუძნებულ ავტორიზაციას.

- პაროლები ინახება ჰეშირებული სახით.
- დაცულ API მოთხოვნებზე მოწმდება მომხმარებლის ტოკენი.
- სხვადასხვა როლს განსხვავებული უფლებები აქვს.
- ადმინისტრატორის ფუნქციები ხელმისაწვდომია მხოლოდ Admin როლისთვის.
- ექიმს შეუძლია მხოლოდ მასთან დაკავშირებული ვიზიტების ნახვა.
- მონაცემები მოწმდება Backend-ის მხარესაც.

## 📅 ვიზიტების დაჯავშნის პროცესი

1. პაციენტი შედის საკუთარ ანგარიშში.
2. ირჩევს ექიმს.
3. უთითებს ვიზიტის თარიღს.
4. სისტემა აჩვენებს ხელმისაწვდომ საათებს.
5. პაციენტი ავსებს დაჯავშნის ფორმას.
6. ვიზიტი ინახება მონაცემთა ბაზაში.
7. Admin და შესაბამისი Doctor ხედავენ დაჯავშნილი ვიზიტის დეტალებს.

დაჯავშნის ფორმაში შეყვანილი პაციენტის სახელი ინახება კონკრეტულ ვიზიტთან ერთად და Dashboard-ებზე სწორედ ეს ინფორმაცია გამოიყენება.

სისტემა ასევე ამოწმებს, რომ ერთი ექიმის ერთი და იგივე დრო ორჯერ არ დაიჯავშნოს.
